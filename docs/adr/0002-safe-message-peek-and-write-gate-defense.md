# 消息默认无损采样与三层写保护门禁

大模型在交互过程中极易因误判发出破坏性指令，在 RabbitMQ 中误发 ACK 会导致在途未消费消息永久丢失，误删队列会导致数据全毁。我们决定建立三层安全防御体系：消息采样默认实施 `requeue=True` 且 `ack=False` 的无损窥探；设置 `--allow-write` 启动参数（默认强只读拦截）；对 `purge_queue`、`delete_queue`、`delete_exchange` 等高危动作强制要求 `confirm: bool = False` 参数二次确认，并在未确认时仅返回受影响预估，从根本上防止生产数据灾难。

## 方案权衡 (Considered Options)

- **直接消费移除（默认 ACK）**：极大增加大模型在探查队列堆积时误删业务数据的风险；
- **纯窥探模式（禁止任何 ACK）**：虽然安全，但导致无法手动处理死信或受控出队，削弱了运维灵活性；
- **默认无损窥探 + 显式确认 + 三层门禁（已采纳）**：在绝对数据安全的前提下，保留了受控变更的能力。
